# P2 nodal elements

Stage 36.3 of the FEM stack added **piecewise-quadratic** elements on
top of the v1 piecewise-linear framework. A P2 triangle carries 6
nodes — 3 corners + 3 edge midpoints — and a P2 tetrahedron carries
10 nodes — 4 corners + 6 edge midpoints. The implementation lives in
`crates/molla/src/fem/p2_element.rs`.

## Reference shape functions

In barycentric coordinates the P2 Lagrange basis is:

- **Corners** \\( N_i^c = \lambda_i (2\lambda_i - 1) \\) — value 1 at
  corner \\( i \\), 0 at every other reference point.
- **Edges** \\( N_{ij}^e = 4 \lambda_i \lambda_j \\) — value 1 at the
  midpoint of edge \\( (i, j) \\), 0 elsewhere.

```rust
pub fn p2_tri_shape_functions(bary: [Real; 3]) -> [Real; 6];
pub fn p2_tet_shape_functions(bary: [Real; 4]) -> [Real; 10];
```

Edge ordering is fixed for the rest of the pipeline so the assembly
and `P2DofMap` agree:

```rust
pub const TRI_EDGES: [[usize; 2]; 3] = [[0, 1], [1, 2], [2, 0]];
pub const TET_EDGES: [[usize; 2]; 6] = [[0,1],[0,2],[0,3],[1,2],[1,3],[2,3]];
```

Tri layout: `[c0, c1, c2, e01, e12, e20]`.
Tet layout: `[c0, c1, c2, c3, e01, e02, e03, e12, e13, e23]`.

The reference-element identities the v1 tests pin down:

- **Partition of unity:** \\( \sum_i N_i \equiv 1 \\) at every
  barycentric point. Checked at the centroid in
  `p2_tri_partition_of_unity_at_centroid`.
- **Kronecker delta on nodes:** \\( N_i \\) is 1 at its own node and
  0 at every other reference node.

## Physical-space gradients

The physical-space gradients follow from the chain rule
\\( \nabla N(\lambda) = \sum_k (\partial N / \partial \lambda_k) \nabla \lambda_k \\),
where \\( \nabla \lambda_k \\) are the P1 hat-function gradients
(constant per element):

- **Corner:** \\( \nabla N_i^c = (4\lambda_i - 1) \nabla \lambda_i \\).
- **Edge:** \\( \nabla N_{ij}^e = 4(\lambda_j \nabla \lambda_i + \lambda_i \nabla \lambda_j) \\).

```rust
pub fn p2_tri_shape_gradients(bary: [Real; 3], vertices: &[Vec3; 3]) -> [Vec3; 6];
pub fn p2_tet_shape_gradients(bary: [Real; 4], vertices: &[Vec3; 4]) -> [Vec3; 10];
```

The gradient routines also satisfy a "partition of zero" identity
\\( \sum_i \nabla N_i \equiv 0 \\) — captured by
`p2_tri_grad_partition_of_zero_at_centroid` and the tet analogue. This
is what makes \\( K \cdot \mathbf{1} = 0 \\) on every cell, which the
mass-conservation contract tests rely on.

## `P2DofMap` — corner + edge addressing

The P2 global DoF vector is laid out as:

1. The first `vert_count` entries are the corner DoFs (DoF index
   `i` ↔ vertex `i`).
2. The next `edge_count` entries are the edge-midpoint DoFs, in the
   order returned by [`compute_edges`](./mesh.md#edge-enumeration--compute_edges).

```rust
pub struct P2DofMap {
    pub vertex_count: usize,
    pub edge_id: HashMap<[u32; 2], u32>,
}

impl P2DofMap {
    pub fn build(mesh: &FemMesh) -> Self;
    pub fn ndof(&self) -> usize;                   // vertex_count + edge_count
    pub fn edge_dof(&self, a: u32, b: u32) -> usize;
    pub fn local_to_global(&self, cell: &FemCell, local_idx: usize) -> usize;
}
```

`local_to_global` handles both halves of the layout:

```text
Local idx (Tri)  →  Global DoF
  0..3              vertex_count[i]           (corner)
  3..6              vertex_count + edge_id    (edge midpoint)

Local idx (Tet)  →  Global DoF
  0..4              vertex_count[i]           (corner)
  4..10             vertex_count + edge_id    (edge midpoint)
```

A 2 × 2 × 2 tet grid has 27 vertices and 98 unique edges, giving 125
P2 DoFs total — the `p2_nodal_ndof_is_vertex_plus_edge_count` test
verifies this.

## Element matrices

```rust
pub fn compute_element_p2_mass(cell: &FemCell, vertices: &[Vec3]) -> Vec<Vec<Real>>;
pub fn compute_element_p2_stiffness(cell: &FemCell, vertices: &[Vec3], coeff: Real) -> Vec<Vec<Real>>;
```

Both kernels return an `N × N` row-major dense matrix
(`N = 6` for Tri, `N = 10` for Tet) by quadrature loop:

```rust
for q in &qpts {
    let n = p2_tri_shape_functions(q.bary);
    let w = q.weight * area;
    for i in 0..6 { for j in 0..6 {
        m[i][j] += w * n[i] * n[j];
    }}
}
```

Quadrature choices:

| Integrand               | Degree | Tri rule        | Tet rule        |
|-------------------------|--------|-----------------|-----------------|
| `Nᵢ · Nⱼ` (mass)        | 4      | 6-pt Dunavant   | 11-pt Keast     |
| `∇Nᵢ · ∇Nⱼ` (stiffness) | 2      | 6-pt (overkill) | 11-pt (overkill)|

The 11-pt rule on tets is overkill for P2 stiffness (the integrand is
only quadratic in the barycentric coordinates) but reusing the same
rule for both mass and stiffness keeps the kernel simple — one
quadrature pass per cell shared with the mass. The 5-pt Keast rule
would be sufficient and is exposed for callers who need to optimise.

Sanity tests in `p2_element.rs::tests`:

- `p2_tri_mass_total_equals_area` — \\( \sum_{ij} M_{ij} = \int_K 1 \cdot 1 = |K| \\).
- `p2_tet_mass_total_equals_volume`.
- `p2_tri_stiffness_kills_constant_field` — \\( \sum_j K_{ij} = 0 \\)
  for each row (a constant field has zero gradient).
- `p2_tet_stiffness_kills_constant_field`.

## Global P2 assembly

```rust
pub fn assemble_global_p2<F>(
    mesh: &FemMesh,
    map: &P2DofMap,
    element_visitor: F,
) -> Result<BsrMatrix>
where
    F: Fn(&FemCell, &[Vec3]) -> Vec<Vec<Real>>;
```

Mirrors [`assemble_global`](./assembly.md#the-visitor-pattern) but
uses `P2DofMap::local_to_global` to translate local node indices →
global DoF indices instead of the simpler `vertex_idx * dim + comp`
formula used by P1. The scatter loop is otherwise identical: build a
flat triplet vector, hand to `BsrMatrix::from_scalar_triplets`.

For the matching vector-valued case (Taylor-Hood velocity), the
`FunctionSpace::P2Vector { dim }` space layers `dim` components per
node on top of the same corner+edge address space — see the
[Stokes chapter](./stokes_ns.md) for the assembler that uses it.

## Why P2 matters

Three reasons:

1. **Higher convergence rate.** Best-approximation error scales as
   \\( O(h^2) \\) for P1, \\( O(h^3) \\) for P2. For smooth solutions
   this means a 2× mesh refinement cuts error by 4× (P1) vs 8× (P2) —
   the cross-over where P2 is cheaper per unit error is small.
2. **LBB stability for Stokes.** The Taylor-Hood pair (P2 velocity,
   P1 pressure) is **inf-sup stable**, where P1/P1 is not. This is
   what makes the Stokes solver in [`stokes`](./stokes_ns.md) actually
   converge.
3. **Curved geometry.** P2 elements can capture quadratic boundary
   deformation; P1 cannot. The viewer scenes for the higher-order
   demos (curvy heat, jellyfish soft body) lean on this.
