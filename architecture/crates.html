molla — Rust + WGPU Physics Engine

Crate boundaries

molla is being modularized by functionality. The current workspace has the foundation crates molla-core, molla-math, molla-storage, runtime-only molla-compute, tiled compute primitive crate molla-compute-primitives, data-model crate molla-sim, host optimizer crate molla-optim, the first molla-actuators slice, the first molla-kernels slices, the first molla-sensors slice, the first molla-geometry slice, the first molla-solvers slice, the first molla-autograd slice, the first molla-fem slice, and the wheeled-vehicle crate molla-vehicle extracted; molla remains the public facade plus remaining engine modules; bin/molla_viewer is the binary-only Bevy application.

The rules

  1. Library crates know nothing about Bevy, ROS, JSON, YAML, or external asset formats. The main molla facade/engine only knows about simulation data, solvers, kernels, and physics modules it owns.
  2. bin/molla_viewer is allowed to depend on Bevy + bevy_egui + bevy_frost + bevy_glacial + mimalloc. That is the full surface; the viewer binary package is the only place those dependencies live.
  3. No importer/exporter or external solver-wrapper crates. Procedural model construction is the supported surface; physics modules own physics data and kernels only.
  4. Optional native dependencies are behind Cargo features. See features.md. The features gate compilation of whole modules so a clean cargo build on a stock Rust toolchain succeeds without SuiteSparse / LAPACKE installed.
  5. There is no Python in the build graph. The xtra/ trees are read-only references and are not workspace members.

Modularization direction

The accepted direction is functional crate boundaries, not CPU-vs-GPU splits. crates/ is for reusable libraries, bin/ is for runnable applications, and crates/molla remains the public facade that preserves molla::prelude::*.

The exclude = ["xtra"] line is what stops cargo build from ever descending into the Newton / Warp reference trees. They are read-only references kept side-by-side in the repository for convenience.

Dependency rules for outside users

If you depend on molla from another crate:

  • Default features include gpu — your build will pull wgpu
    • pollster. Use default-features = false to skip those if you only want the CPU paths.
  • russell is off by default and reserves the direct-solver surface for optional sparse-linear-algebra experiments. The current implementation stays pure Rust in the nix dev shell.
  • The prelude is stable. Anything outside prelude may move between minor releases until 0.1.0.

The crate is on 0.0.1 at present; no SemVer guarantees yet. The PLAN’s quality bar is that every shipped feature has a trajectory or unit test, an example, a bench, and CPU/GPU parity — that is the unofficial release criterion.
