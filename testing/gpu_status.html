molla — Rust + WGPU Physics Engine

GPU port status matrix

A comprehensive table of which solvers, kernels, sensors, actuators, and FEM steppers have GPU paths today, which have CPU-only implementations, and which have parity tests.

Notation:

  • GPU — full GPU dispatch path exists.
  • CPU — CPU reference implementation (oracle).
  • Parity — tests/<name>_gpu.rs exists and asserts CPU/GPU agreement.
  • CPU-only — only the Rust path ships; no WGSL kernel.

Summary

  • Every solver in prelude has a GPU path and a parity test.
  • Every sensor has a GPU path and a parity test.
  • Every actuator has a GPU path; most have dedicated parity tests, the rest are covered by pipeline tests.
  • The vast majority of FEM steppers have GPU paths. A handful (AMR, magnetostatics, full Signorini, some adjoint paths) ship CPU-only with the GPU port still on the roadmap.
  • Compute primitives (tile, FFT, sort, scan, BSR, splat) are GPU with CPU oracles.

The CPU paths are not deprecated — they remain the debugging path and the oracle for parity testing. The “GPU port still on the roadmap” status applies to a small number of FEM and MPM sub-paths and is tracked in PLAN.md and GAP_v2.md.
